# 阶段04：1015/1035 线条角色判断分类调研报告

## 结论摘要

下一步不应把角色判断实现成“候选线属性分类”或“按轨迹长度排序”。当前 1015、1035 的输入已经从局部候选整合成了允许弯曲的中性轨迹，但角色判断仍需要一个全局结构层：

```text
原图/二值/骨架/候选证据
        ↓
软轮廓轨迹（当前阶段04实验结果）
        ↓
轨迹几何、像素支持、交点拓扑、左右顺序和相互间隔特征
        ↓
全局非交叉结构选择
        ↓
frame / table_boundary / separator / internal_or_noise / uncertain
```

角色判断必须同时回答两件事：

1. 哪些轨迹属于表格的外层框线、主体边界和列分隔线；
2. 哪些轨迹虽然在图像中可见，却是水纹、内部记录线、文字或其他干扰。

因此，建议采用“候选轨迹软评分 + 非交叉有序结构选择 + 角色后验分类”的最小实验。对于证据不足的轨迹保留 `uncertain`，不强行升级为表格线。

本报告只做调研和下一步方案设计，不修改生产角色入口、不计算列数、不进行 OCR 或单元格恢复。

## 二、调研到的方法论

### 1. 线段检测只是低层证据，不能直接承担角色判断

OpenCV 官方文档把概率 Hough 变换定义为从二值图像中寻找线段；它适合提供直线段证据，但参数本身包含累加器阈值、最小长度和最大间隔等检测选择。官方形态学教程也明确说明，线性结构元素适合提取水平或垂直的直线结构。两者都不能单独区分“表格列分隔线”和“水纹/文字形成的局部直线”。

- [OpenCV：概率 Hough 线变换](https://docs.opencv.org/5.0/tutorials/imgproc/imgtrans/hough_lines/hough_lines.html)
- [OpenCV：用形态学操作提取水平线和垂直线](https://docs.opencv.org/5.0/tutorials/imgproc/morph_lines_detection/morph_lines_detection.html)

LSD 论文提出了带 false-detection control 的线段检测器，并强调线段是图像几何的低层表示；曲线会被分解为若干局部近似直线段，曲率过大时检测能力会下降。这与本项目的经验一致：候选 `label/direction/length` 只能作为证据强度，不能作为最终角色。

- [Grompone von Gioi 等：LSD: A Fast Line Segment Detector with a False Detection Control](https://dev.ipol.im/~qbammey/anne/LSD_A_Fast_Line_Segment_Detector_with_a_False_Detection_Control.pdf)

**对本项目的含义：**保留现有候选检测和软轮廓结果；角色判断使用轨迹的全高覆盖、连续性、局部方向、像素贴合和结构关系，不能重新退回单候选硬门槛。

### 2. 断裂、弯曲线应使用全局一致性而不是只拟合一根直线

“Model-based ruling line detection in noisy handwritten documents”把 ruling line detection 建模为多线回归，并强调显著但可能不连续、不完整的 ruling-line 片段应通过全局模型合并。该思路适合借鉴“多条线共同选择”和“缺口不等于不存在”，但本项目原图存在倾斜和局部弯曲，不能直接套用严格直线模型。

- [Model-based ruling line detection in noisy handwritten documents](https://doi.org/10.1016/j.patrec.2012.08.008)

本项目应使用其全局一致性思想，而把模型残差改为允许弯曲的局部切向残差、曲率变化和轨迹顺序约束。这样可以针对用户指出的“列→岩层→列”错误加入扭曲惩罚，同时不会把所有真实弯曲线强行拉直。

### 3. 轮廓整合应累积局部方向、位置和连续性

Field、Hayes、Hess 的 contour integration 研究以“good continuation”为核心，讨论局部方向元素如何根据空间接近和方向相容性形成连续轮廓。它不是表格识别算法，但为本项目上一轮采用的软证据累积提供了方法论依据：局部证据不应被一个孤立硬阈值立即丢弃，沿稳定方向、位置连续排列的弱片段可以共同形成更强轮廓。

- [Field、Hayes、Hess：Contour Integration by the Human Visual System](https://dev.ipol.im/~blusseau/biblio/psychophysics/1993-field-hayes-hess--contour-integration-by-the-human-visual-system.pdf)

**对本项目的限制：**轮廓连续性本身也会增强水纹，因此必须再叠加表格拓扑和互斥顺序约束；不能把显著度最高的轨迹直接宣布为真实列线。

### 4. 表格结构识别需要 top-down / bottom-up 和关系约束

ECCV 2020 的 table structure recognition 工作把单元格检测与行列关系预测结合，明确指出仅依赖 PDF 元数据或 OCR 低层特征难以泛化，并将 top-down 的单元格/区域证据与 bottom-up 的结构关系结合。虽然本项目暂时不做 OCR 和单元格识别，但“局部视觉证据 + 全局行列关系”这一分工适用。

- [Raja、Mondal、Jawahar：Table Structure Recognition using Top-Down and Bottom-Up Cues](https://www.ecva.net/papers/eccv_2020/papers_ECCV/papers/123730069.pdf)

TGRNet 将表格表示为包含空间位置和逻辑位置的图，并把结构识别转化为图关系重建；相关工作说明，单独的局部检测不能表达列顺序、相邻关系和跨区域依赖。

- [Xue 等：TGRNet: A Table Graph Reconstruction Network for Table Structure Recognition](https://openaccess.thecvf.com/content/ICCV2021/papers/Xue_TGRNet_A_Table_Graph_Reconstruction_Network_for_Table_Structure_Recognition_ICCV2021_paper.pdf)

另有面向表单/文档的 bottom-up 图方法，把低层 primitive 先表示成节点和边，再用关系分类与共识层识别结构；这支持本项目把轨迹作为节点，把相邻、交点、顺序和不交叉关系作为边。

- [Table Structure Recognition and Form Parsing by End-to-End Object Detection and Relation Parsing](https://www.sciencedirect.com/science/article/pii/S0031320322004265)

### 5. 评价必须防止过分割、漏线和误吸被混在一个数字里

PubTables-1M 论文专门讨论了 table structure 标注中的 oversegmentation，并通过规范化保证结构解释一致；这提醒我们：本项目不能只看“轨迹数量”或“显著度总分”，而应分别检查真实边界的断裂、重复、跳线以及水纹/文字的误收。

- [Smock、Pesala、Abraham：PubTables-1M](https://openaccess.thecvf.com/content/CVPR2022/html/Smock_PubTables-1M_Towards_Comprehensive_Table_Extraction_From_Unstructured_Documents_CVPR_2022_paper.html)

下一轮应采用可复查的逐轨迹验收表，而不是编造准确率或把 1015 的既有列数当作真值。

## 三、适合本项目的角色分类方案

### 3.1 角色不是从原始 label 直接映射

原始 `high/suspect/noise`、全局 `direction` 和长度保留为输入特征，不修改其值，也不做如下直接映射：

```text
high     → separator
suspect  → reject
noise    → internal
```

原因是 1035 候选 9 已经证明：一个混合 polyline 可以含有真实纵向上半段，但全局属性仍为 `suspect/none`；反过来，长且连续的水纹也可能获得较高局部显著度。

### 3.2 轨迹级特征

每条软轨迹计算归一化特征，尽量使用图像自身尺度，不使用 1015/1035 专用坐标：

| 特征组 | 具体证据 | 主要用途 |
|---|---|---|
| 像素支持 | 二值图/骨架图上的覆盖率、支持长度、缺口分布 | 排除只有候选几何而无像素依据的线 |
| 纵向持续性 | 覆盖高度、分窗占用率、最大连续缺口、首尾端接 | 识别主体边界和列分隔线 |
| 局部几何 | 局部切向纵向程度、横向残差、曲率、曲率变化 | 惩罚水纹、文字和“列→岩层→列”跳线 |
| 全局位置 | 归一化 x 位置、各高度窗口的 x 中位数和波动 | 维持左右顺序，避免跳到相邻列 |
| 相互关系 | 相邻轨迹间距、交叉次数、同一候选复用、左右顺序稳定性 | 选择非交叉列结构 |
| 端点/交点 | 与横向结构的交点支持、端接和包围关系 | 区分框线/主体边界与孤立内部线 |
| 干扰特征 | 局部摆动次数、反复折返、局部密集但全高不连续、文字区共现 | 降低水纹、文字和岩层内部线的角色分数 |

### 3.3 建议的角色层次

先进行“是否属于表格纵向结构”的判定，再在结构内细分角色：

1. `frame`：构成外层包围关系、具有较长纵向持续性，并得到边界端接/横线交点支持的轨迹。
2. `table_boundary`：构成表格主体区域边界，但不一定是整张图的最外框；需要主体上下范围、邻接列结构或横线端接支持。
3. `separator`：位于已选主体边界之间，左右顺序稳定、纵向持续性和像素支持足够，并与相邻结构形成合理间隔的轨迹。
4. `internal_or_noise`：主要由内部记录、水纹、文字或孤立局部片段支持；缺乏稳定表格拓扑，或扭曲/折返代价过高。
5. `uncertain`：证据相互冲突时保留不确定状态，进入人工复核，不强行分类。

这里的 `frame`、`table_boundary` 和 `separator` 是语义角色，不依赖固定列数，也不依赖 1035 的 x 坐标。尤其不能把最左或最右轨迹仅凭排名自动判为 frame；需要检查它是否真的形成包围/端接结构。

### 3.4 全局结构选择

将软轨迹作为节点，把两条轨迹的相邻关系、间距稳定性、横线交点一致性和是否交叉作为边权。求解时加入以下约束：

- 轨迹在从上到下的窗口中左右顺序尽量不变；
- 互相交叉或突然横向跳跃的组合付出高惩罚；
- 同一候选片段不能同时属于两条互斥主轨迹；
- 主结构应覆盖相对较大的共同高度范围；
- 允许真实轨迹有缺口和局部弯曲，但不允许用理想轴对齐直线补齐；
- 不满足结构证据的高显著度轨迹仍可被拒绝或标记 `uncertain`。

这个阶段可以使用已有 NumPy、OpenCV、SciPy/sklearn 能力，不引入新依赖。第一版优先采用有序轨迹图和动态规划/最大权非交叉选择，不实现完整的深度学习表格识别器。

## 四、下一步最小实验设计

### 阶段R1：只计算角色特征

- 输入仅限 1015/1035 的现有候选 JSON、二值/骨架证据和上一轮软轮廓轨迹；
- 不修改候选原始 `label/direction`，不写角色回原 JSON；
- 输出每条轨迹的特征、各角色分数、拒绝原因和 `uncertain` 原因；
- 输出全分辨率特征诊断图，显示轨迹 ID 和关键分数。

验收：能在实际 JSON 中追溯每个分类结论的候选成员与像素证据。

### 阶段R2：全局非交叉结构选择

- 使用同一套数据派生尺度处理 1015、1035；
- 先选表格纵向结构集合，再计算 `frame/table_boundary/separator` 角色；
- 水纹和内部线只能通过证据和结构惩罚被排除，不使用图名或坐标特判；
- 输出全部轨迹、选中结构、拒绝轨迹和不确定轨迹四类图层。

验收：

- 外层框线、主体边界和真实列分隔线各自保持连续、贴合像素且不跳线；
- 内部线、水纹和文字不被大面积纳入选中结构；
- 1035 已知的局部“列→岩层→列”错误不被角色分类放大；
- 1015 不出现明显的边界断裂、重复或跳到相邻线；
- 不宣称真实列数或准确率，等待用户查看完整分辨率图。

### 阶段R3：角色图层交付

只在 R1/R2 通过后输出：

- `frame`、`table_boundary`、`separator` 的统一角色叠加图；
- `internal_or_noise` 和 `uncertain` 的独立拒绝/待审图；
- 每条轨迹的 JSON 诊断，包括成员候选 ID、角色分数、像素支持和拒绝理由；
- 1015/1035 完整分辨率图和最容易误判区域的局部放大图。

尚不进入 OCR、行恢复、单元格恢复或正式角色生产入口。

## 五、风险与停止条件

### 主要风险

1. 水纹具有长距离连续性，可能在“只看连续性”的评分中被误升；因此必须依赖曲率/摆动、横线交点和左右顺序共同约束。
2. 外框线和主体边界可能在局部共享端点；若没有足够的横线端接或包围证据，应输出 `uncertain`，不能用 x 排名强行区分。
3. 文字和岩层线可能在某些区段与列线相交；只能利用全高结构和非交叉全局选择，不能依据局部交点单独判定。
4. 1015 现有结果约为 10 列只是防回归线索，不是真值，不能用作训练标签或正确率分母。

### 立即停止条件

- 需要为 1015 或 1035 写专用坐标、图片名或阈值；
- 角色分类无法用实际轨迹 ID、像素支持和关系诊断解释；
- 1015 明显退化；
- 选中结构明显增强大量水纹、文字或内部岩层线；
- frame 与主体边界无法由现有证据区分，却必须强行给出唯一标签；
- 需要 OCR、外部标注或新依赖才能继续；
- 需要修改生产入口才能验证实验。

## 六、调研后的实施建议

建议下一步只实现 R1：在现有中性轨迹上计算角色特征和可解释分数，并生成 1015/1035 的全分辨率诊断图；R1 通过后再实现 R2 的全局非交叉结构选择。这样可以先确认水纹、文字和真实列线的特征差异，再决定是否需要调整权重，不把候选检测、轮廓整合、角色规则和结构恢复同时改变。

本报告的核心判断是：

> 角色判断应是“轨迹证据 + 表格拓扑 + 全局互斥结构”的问题，而不是原始候选标签的重新命名。
