# 调研与设计:当前阻塞 → 开发界方案 → 基建先行落地(路径A)

日期:2026-09-30
状态:问题映射与路径A 已获用户确认;本文供用户审阅,通过后转 writing-plans
范围:四类阻塞逐一映射。**本设计只交付三件基建工具 + 决策队列**;后续各刀(真断口补齐/补漏线/rowspan/P0/6b/reemit)技术方向不变、仍按 STATUS.md §5,不在本文展开。

## 1. 结论

- 四类阻塞在开发界都有成熟对应模式,无需发明新方法;全部落地可用现有栈(stdlib/numpy/cv2),不引重型依赖(用户拍板:方法论为主+轻量库)。
- 真正的瓶颈不是"缺刀",是**每把刀都要付一遍全额核验成本**、且**产物漂移没有机制性发现手段**。两者是基建问题,不是算法问题。
- 拍板:**路径A 基建先行**——先建 ①diff核验器 ②manifest指纹 ③决策队列,之后所有刀与核验轮都踩在其上。终局"30 张全分辨率叠加图 + 用户肉眼核验"口径不变(约束7)。

## 4. 三件基建工具设计

### 4.1 工具① diff 核验器 `src/tools/review_diff.py`

- **目的**:把"每轮全图重看"降为"每轮只看增量"。终局核验仍是全分辨率叠加图 + 用户肉眼,不变。
- **输入**:同 stem 的新旧两版结构 JSON(参数指定,如两代行列线数据集的 `{stem}.json`、或刀前刀后的 `{stem}_分割线.json` 派生段)。
- **主 diff(数据级,不做像素级)**:线集合按 id 对齐 → 逐线坐标残差 → 分类:新增/消失/位移(>阈值 px)/不变。位移阈值不预设常数,以两代数据的实测残差分布定并在提交时附推导链(参数口径既有约束)。
- **输出**:每图 `diff账目.json`(逐线分类+最大残差)+ 变更线的 1:1 对照裁片(旧/新并排,bbox=变更线折点范围外扩 150px);零变更图只记一行账。
- **可选像素级兜底**:两版线各自重渲到白底后再做像素 diff(规避叠加图底图的扫描噪声,不直接 diff 扫描叠加图)。
- **边界**:逐图处理读后即释(emit 先例峰值 ~390 MB);路径一律走 `paths.py`。
- **测试**:构造小 JSON+小图 fixture,断言分类正确、裁片尺寸、零变更短路。

### 4.2 工具② manifest 指纹 `src/tools/make_manifest.py` + audit 对照模式

- **目的**:漂移从"偶然发现"变"必然报警";已核验产物可钉成 golden master。
- **生成**:对产物目录写 `_manifest.json`:`files{相对路径: md5}` + `generated_by`(脚本名)+ `code_commit`(git HEAD)+ `sources{输入文件: md5}` + `params`。`emit_line_dataset` 已写源 md5,此为推广。
- **对照**:`audit_line_dataset.py --against-manifest <目录>` 逐文件比对 md5,报 新增/缺失/变更;退出码非 0 = 漂移。
- **边界**:工具无条件交付;但"给 `runs/table_reconstruct` 核验产物铸基线"= D06 裁决事项,**执行前对核验产物只读不动**。
- **测试**:md5 稳定性;篡改一文件后对照必报、退出码非 0。

### 4.3 工具③ 决策队列(gate_ledger 增设区段,无代码)

- `memory-bank/gate_ledger.md` 增设 `## 决策队列` 区段,字段:`ID / 事项 / 背景 / 选项 / 推荐 / 状态(待裁|已裁) / 裁决+日期`。
- 预填 §5 的 D01~D09;此后所有"待用户裁决"一律入队,不再散落。
- 纯文档约定,无测试;audit 不校验。

## 6. 错误处理与约束合规

- **不碰结构线**:三件工具均不生成/修改/拼接任何结构线,约束2 无涉。
- **约束7/10**:diff 与 manifest 只降低核验成本、发现漂移;结构正确性口径(全分辨率叠加图+用户肉眼)不变;助手判读仍只作弱档预筛。
- **约束1**:工具产物一律写新目录,不回写基线;rollback/ 目录不动、不作输入。
- **路径A 不改变任何刀的技术方向**:补漏线、断口外延、rowspan、P0 重推、6b、reemit 仍按 STATUS §5,本文只解决"核验怎么付钱、漂移怎么发现、裁决怎么管"。

## 7. 验收标准

1. `review_diff.py` 单测绿;真实数据跑通两代行列线数据集(20260926 vs 列线分段_20260927)的 5 张交集图:**行线几何坐标应零变更**(两代同一行模型;账目/字段结构差异不算)、**列线变更=表征切换**(v1 排序折线 → v2 逐碎片段,267 条全量位移/重分类属预期)——账目须能对上这两个已知事实,对不上即工具或理解有误。
2. `make_manifest.py` 对 `outputs/行列线数据集_列线分段_20260927/` 出 manifest 且 audit 对照过;人为篡改一文件后 audit 退出码非 0。
3. gate_ledger 决策队列预填 9 条。
4. `pytest -q` 全绿(新增测试不破 163 基线)。
