## 1. 阶段4：表格线候选识别

### 1.1 阶段4 给了我们什么（一句话）

阶段4 把"细化骨架"变成**带方向、标签、几何特征与结构分数的候选线段集合**，每张图一个 JSON，共 43k~76k 条候选线段，每条线包含原始坐标点（RDP 简化后）和 14 个特征字段。它**不做结构恢复**，只负责"哪些像素轨迹可能是表格线、各自有多可信"。

### 1.2 输入

1. **阶段3 折线坐标 JSON**（只读）：`data/LingDong-skeleton-tracing处理/坐标数据/钻孔柱状图{编号}.json`
   - 字段：`image, width, height, num_polylines, num_points, polylines`。
   - `polylines` 是折线数组，每条折线是 `[[x,y],...]` 的坐标点序列。
   - 三张测试图规模：
     - 1015：52976 条折线、414458 个点、图 3200×18661
     - 1027：43657 条折线、341122 个点、图 3192×14088
     - 1035：76448 条折线、561996 个点、图 3280×20941
2. **原始扫描 JPG**（只读）：`data/raw_images/钻孔柱状图{编号}.JPG`，仅用作原图副本与叠加背景，不参与几何计算。

### 1.3 处理流程（三阶段 A→B→C）

对每一条阶段3 折线执行以下步骤：

**阶段A：几何简化与特征提取**

1. **RDP 简化**（Ramer–Douglas–Peucker，自实现，`rdp()`）：
   - 阈值 `RDP_EPS = 2.0 px`，消除骨架锯齿，保留主方向。简化后的点序列存入最终 JSON 的 `points`。
2. **六维几何特征**（`compute_features()`）：
   - `length`：折线累计长度；
   - `direct_ratio`：累计长度 / 首尾弦长（直线≈1.0，弯折文字笔画更大）；
   - `angle`：首尾连线方向角（0~180°）；
   - `w, h, w_over_h`：包围盒宽、高、宽高比；
   - `bbox = [x0,y0,x1,y1]`、`midx = (x0+x1)/2`、`midy = (y0+y1)/2`。
3. **PCA 主方向**（`pca_angle()`）：对简化点集中心化后 SVD，第一主成分方向角（0~180°）。
4. **局部方向稳定性**（`deflection_std()`）：相邻段方向差（折叠到 0~90°）的标准差，度量"直不直"。

**阶段B：方向判定与三级初分**

5. **主方向判定**（`classify_direction()`）：PCA 方向与包围盒宽高比双重确认，方向容差 `DIR_TOL = ±5°`：
   - 水平：PCA 角≈0° 且 `w_over_h > 3.0`；
   - 垂直：PCA 角≈90° 且 `w_over_h < 0.33`；
   - 否则 `none`。
6. **三级初分**（`initial_label()`）：
   - `high`：`length >= 100px` 且方向非 none 且 `direct_ratio <= 1.1`；
   - `suspect`：`50px <= length < 100px` 且方向非 none；或长度≥100 但直达比>1.1；或长度≥150 但方向 none；
   - `noise`：其余（短且方向不正，多数是文字笔画）。
   - 依据：探查发现长度≥100px 的候选纯度 99%+；<50px 基本是文字笔画（94~95%）。

**阶段C：DBSCAN 线带聚类 + 结构支持打分 + 标签复核**

7. **一维 DBSCAN 聚类**（`cluster_bands()`，`sklearn.cluster.DBSCAN`）：
   - 对 high+suspect 候选分别按横线 `midy`、竖线 `midx` 做一维聚类，`eps=15px, min_samples=2`。
   - 得到 `band_id`（-1 表示孤立点）与 `band_size`（同线带候选数）。
8. **结构支持打分**（`compute_struct_scores()`）：
   - `band_support = min(band_size/5, 1.0)`：同一线带的候选数（≥5 条满分）；
   - `span_coverage = min(length/主跨度, 1.0)`：主跨度取同向候选长度的 p75；
   - `crossing_count`：与垂直方向候选的首尾段交点数量（`segments_intersect` 叉积法），`crossing_support = min(cross/3, 1.0)`；
   - `struct_score = 0.4*band_support + 0.3*span_coverage + 0.3*crossing_support`；
   - `geo_score = 0.5*min(length/300,1) + 0.3*(1-|direct_ratio-1|) + 0.2*(1-deflection/5°)`；
   - `final_score = 0.6*geo_score + 0.4*struct_score`。
9. **标签复核**：`suspect` 且 `struct_score>=0.5` 提升为 `high`；`high` 但 `struct_score<0.1` 且 `band_size<=1` 降为 `suspect`。
   - 注意：复核后仍保留所有线，只改标签，**不删除任何线**。

## 2. 阶段5：表格真实列线识别

### 2.1 目标与设计约束（用户明确的原则）

- 列线只能由阶段4 候选段构成，**不创造原图不存在的线**、不延伸端点、不做分箱重采样。
- **连续性优先于坐标**：不用固定 X / midx 分组，不用单一全局斜率校正，不用 Hough 直线直接决定结构，不用简单 DBSCAN x 聚类恢复列。
- 断口补齐必须同时满足三点：两端斜率像、延伸后能对齐、中间缺口能用同斜率（近垂直）线补上。
- 真列线特征：连续平直、具分隔作用、顶底相连、整体波动小；**不把表格外框当作列分隔线**；内部结构线不是列。
- 不硬编码列数；自动指标只证明结构性质，不冒充 precision/recall；最终必须人工全分辨率核验。

### 2.2 输入

- 阶段4 坐标 JSON：`data/表格线候选识别处理/坐标数据/钻孔柱状图{编号}.json`。
- 实际只用其中 `label=="high"` 且 `direction=="vertical"` 的候选段。
- 原始 JPG 仅用于叠加图/诊断图背景。

### 2.3 方法（总体思路：从"竖向碎片拼线"改为"整张表结构锚点 + 身份约束"）

旧的阶段5 思路是"竖向 high 碎片 → 局部贪心拼接 → 大缺口拼接 → 长度/斜率/平滑度筛选"。它的根本缺陷：把"长、直、竖、平滑"当成了"真实列边界"，导致（a）真列线断口一次断裂就丢身份；（b）柱状图/曲线图内部竖线被误选；（c）允许缓慢横漂把 A 列平滑串到 B 列。

新方法的核心是：**列的身份由整张表的横向结构给出**——表格的水平行线（横向候选段）的左右端点必然落在列边界上；因此用水平段端点的 x 位置聚类出"列边界锚点"，然后每个竖向碎片只能归属于最近的锚点走廊。这样：

- 真列线中间断掉一大段，只要仍在同一锚点走廊内，身份不丢（记录 gap，不强行画长线）；
- 内部结构竖线不承担分列作用，水平行线不会在它那里起止，所以它成不了锚点、也不落任何锚点走廊，被单独归为内部结构；
- 每个 run 只属于一个锚点走廊（最宽 ±30px、密集处自动收窄），从构造上禁止从一条列边界漂移到相邻列边界。

### 2.4 处理流程（当前实现，按执行顺序）

**步骤1：run 化**（`split_runs()`）
把每条 vertical+high 候选段按原始点序列切成"竖直 run"：
- 相邻点 `|dx/dy| > 2.0`（近水平跳变）或 `|dx|>50px 且 |dx/dy|>0.5` 处切分；
- 丢弃 y 跨度 <30px 的碎片；
- 每个 run 保留原始点（画图用），并计算 `y0,y1,x_top,x_bot,x_med,y_mid,k,b,span,resid`。

**步骤2：表框估计**（`estimate_table_bounds()`）
取水平 high 段中跨度 ≥0.35×最大水平跨度的"通栏行"，用其 y 范围估计表顶/表底。

**步骤3：列边界锚点发现**（`discover_anchors()` / `_header_anchors()` / `_hist_peaks()`）
- **表头行边界（受保护锚点）**：表顶往下 700px 内，把水平段按行聚类（y 差≤12px 视为同一行），行内每个单元格的左/右端点就是列边界；跨行按 x 聚类（eps=15px）统一。单行只出现一次的 rowspan 子边界也不会丢。
- **全表端点直方图峰（补充锚点）**：取所有长度≥40px 的水平段左右端点，做 6px 直方图 + 高斯平滑（σ=2 bin）后找局部峰，峰间距≥40px、端点计数≥3；用于补充表头以下才出现的 rowspan 子边界。
- 峰锚点若距表头锚点 <25px 则丢弃（避免 30~35px 间距的子边界被合并）；非表头峰锚点之间 ≤20px 才合并。
- 每个锚点用其附近 ±18px 的水平端点拟合一条 `x = k·y + b` 走势线（斜率限制在 ±0.03），得到锚点字段 `x, n_ep, n_ep_top, from_header, k, b`。

**步骤4：run → 锚点分配**（`_assign_runs_to_anchors()`）
- 每个锚点的走廊半宽 `x_tol = max(12, min(30, 0.4×最近邻锚点距离))`。
- 每个竖向 run 计算其 `x_med` 到各锚点走势线在 run 中点 y 处的距离，分配给**最近且落在走廊内**的锚点；不在任何走廊内的 run 记为"未分配"（内部结构/外框候选）。
- 保证每个 run 至多属于一个锚点。

**步骤5：锚点内子路径拆分**（`split_anchor_runs()` + `_valid_junction()`）
同一走廊可能吸进两条相距小于走廊宽的平行线。按三点校验把锚点内 run 切成若干子路径（不合格接点断开、不画桥）。三点校验（`_valid_junction`）：
- 重叠超过 15px：非法；
- 重叠/触碰（gap≤0）：`|x残差|≤15px` 且 `|k差|≤0.08`；
- 真实缺口（0<gap≤500px）：`|x残差|≤15px`（延伸对齐）+ 近垂直；小缺口（<20px）斜率噪声大，只要求 `|kb|≤0.5`；大缺口（≥20px）要求 `|kb|≤0.1`，且两端 run 都 ≥150px 时再收紧 `|kb-kA|≤0.05 且 |kb-kB|≤0.05`；
- gap>500px：不画桥，但保留同一锚点身份（断裂不丢列）。
- 主路径 = 覆盖证据（y 并集长度）最多的子路径；其余子路径标记为"平行碎片"，不进列候选。

**步骤6：路径构建**（`build_trajectory()` / `chain_stats()`）
- 每条路径输出：成员 run 的原始点 `polylines` + 经过校验的小桥接 `bridges`（只在 gap≤500px 且三点校验通过时画）。
- 不重采样、不延伸端点。统计字段：`span`（y 跨度）、`coverage`（y 并集覆盖）、`x_range`、`k,b`（最小二乘斜率）、`resid_std/max`、`turns`（相邻 run 斜率差>0.05 的次数）、`gaps`（每个缺口起止与长度）、`member_ids`（阶段4 原始 line id）、`run_ids`。

**步骤7：未分配链**（`_chain_unassigned()`）
未分配的 run 按同样三点校验做竖直链拼接，身份拼接上限 = 0.15×表高（约 2000~2900px），用于把内部结构/外框的同一物理线尽量连成一条。

**步骤8：角色分类**
- **外框 frame**：最左端结构（±45px 内）或超出最右表头锚点 20px 以上的结构，或最右端结构；不列为列分隔线。
- **列候选 column**：锚点主路径，满足 `n_runs≥2`、`coverage≥400px`、`span≥max(600px, 0.08×表高)`。
- **内部/平行 internal**：未分配长链（span≥0.20×表高）或锚点内非主路径的平行碎片。
- **拒绝 rejected**：其余。
- 列候选按 x 排序，计算每列的左右相邻列距离。

自动检查字段（`structure_checks`）：
- `non_crossing`：列路径按 x 排序后在重叠 y 区间是否保持左右顺序；
- `no_run_duplication`：同一 run 是否被两条最终列重复消费；
- `lateral_jump_count`：路径内相邻 run 端点是否大幅横跳（dx>60px 或 |dx/dy|>0.2）；
- `bridge_tilt_violations`：桥接斜率 |dx/dy|>0.5 的数量（当前为 0）；
- `bridge_tilt_warnings`：桥接斜率 0.1~0.5 的数量（均为 5~12px 小缺口上的端点噪声）；
- `columns_local_only`：只存在于局部区段（span<0.3×表高）的列候选数。

内部一致性检查（`raster_assert`）：把输出像素栅格化，验证**输出像素 ⊆ 成员段并集 ∪ 桥接**，`output_px_unexplained==0`。这只证明"没有画出来历不明的像素"，**不证明结构正确**。

### 2.8 已知问题与不确定性（如实声明）

1. **右块窄列**（1015 x≈2350–2530、1027 x≈2369–2843、1035 x≈2412–2574）竖线残破、倾斜明显，哪些是真边界需人工全分辨率确认。
2. **绘图列左右边缘的平行碎片**（1015 x≈960/1002、1027 x≈932/969、1035 x≈848/967/1005）可能同属一条缓慢漂移的边界，是否合并需人工判断。
3. **1035 左块密集区**（x≈644/728/806 附近）存在相距很近的平行线，算法已把它们拆成"列候选 + parallel 碎片"，归属需人工确认。
4. **外框拆分**：右框常裂成多段（如 1015 的 2864/2910/2954），已在 JSON 标为 frame，但归属是启发式。
5. **没有正式人工 ground truth**：本报告所有自动指标只证明结构性质（非交叉、不重复消费、桥接不超斜率、输出像素有来源），**不证明 precision/recall**。

## 3. 术语速查

| 术语 | 含义 |
| --- | --- |
| polyline / 折线 | 阶段3 输出的坐标点序列 |
| 候选段 / line | 阶段4 输出的单条线段记录（含标签与特征） |
| high / suspect / noise | 阶段4 三级标签：高可信 / 可疑 / 噪声 |
| run | 阶段5 把一条 vertical+high 候选段在近水平跳变处切开后的竖直片段 |
| 锚点 / anchor | 由水平段端点聚类得到的列边界 x 位置（列身份） |
| 走廊 / x_tol | 锚点允许吸收竖向 run 的 x 范围 |
| 桥接 / bridge | 两个相邻 run 之间满足三点校验的小缺口补线（≤500px） |
| gap | 路径内无证据的 y 缺口（记录在 JSON，不画长线） |
| 平行碎片 / parallel | 同一锚点走廊内、非主路径的竖向子路径（不进列候选） |
