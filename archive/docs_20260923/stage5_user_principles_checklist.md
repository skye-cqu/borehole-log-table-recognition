# 阶段5 用户核心原则检查清单（强制，每次工作前逐条对照）

> 本文件是用户明确提出的最高优先级原则。**每次读取代码、改动、设计、验证前，先逐条重读本清单**。任何与本清单冲突的做法都是错误的，即使"指标看起来更好"。

## 必查清单（读代码/设计/改码前逐条过）

- [ ] 1. **问题在第五阶段**：第四阶段输出没问题（用户核验确认）。不要把问题归咎于数据源，除非有新的强证据。
- [ ] 2. **忠实数据源**：列线只能由第四阶段候选段构成。禁止创造原图不存在的线条——不桥接远距段、不延伸端点、不分箱重采样重造。
- [ ] 3. **连续性优先于坐标**：不用固定 X / midx / 单一全局斜率判断列线归属。列线倾斜，须用"沿线追踪 + 局部方向一致 + 位置能对接"。
- [ ] 4. **断口补齐三点要求**：斜率像 + 延伸过来能对齐（位置接近能重合）+ 中间缺口能用同斜率线补上。缺一不可；靠斜率差很多的线补、或位置差很远的，都不行。
- [ ] 5. **真列线特征**：连续且平直、具分隔作用、顶底相连、整体波动小（统一斜率）。内部线（折线多/突然转折/短段即转）不是列线。
- [ ] 6. **禁止后处理掩盖**：不用"排除横线/限制列数"等后处理来掩盖算法缺陷。算法正确，自然没有横线/折线/跨列。
- [ ] 7. **验收正确**：先忠实画清楚列线；n_columns 不是本阶段硬门槛；验证必须含视觉健全性（折线/横线/跨列数），不得只用 recall/precision。
- [ ] 8. **第一性原理 + 最小复杂度**：先想清楚"一个真正的表格长什么样、人是怎么看出来的"再定算法；能写一行不写十行；泛化优先，不针对单图特判。
- [ ] 9. **先验证后实现**：每个假设先用只读数据量化验证（给数值证据），确认后再动代码。
- [ ] 10. **最终以用户全分辨率肉眼核验为准**：不擅自宣称某图列线正确。

## 若与历史实现冲突

历史实现（分箱中位、A2 段拼接、X 分组、全局斜率校正）均为失败路线，**不作为设计依据**。遇到与上述原则冲突的历史代码，以本清单为准。

## 工作流提醒

1. 读 memory-bank/activeContext.md（当前任务与事实）→ decisions.md → 本清单。
2. 方向性决策用 fresh context 子代理（避免错误历史污染）。
3. 每次里程碑完成，回到本清单重新对齐一次。
