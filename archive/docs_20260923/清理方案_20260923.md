# 仓库瘦身与结构收敛方案（2026-09-23）

现状：工作区 65 GB（`runs` 50G、`data` 7.1G、`.git` 5.3G、`rollback` 2.3G、`outputs` 21M）。
文档 36 份（`reports` 29 + `memory-bank` 6 + `AGENTS.md`），`AGENTS.md` 同时装约束、进度、脚本对照表。
代码里同一功能 2~3 套实现并存，结构缺陷靠 `repair_1032.py` / `repair_1042.py` 手工补。

本方案做三件事：腾空间、归位文档、把行界判据收敛成一套。删除部分全部可还原。

## 一、腾空间：65 GB → 约 8 GB

实测依据：`runs`/`data`/`outputs` 中 >5 MB 的位图里，**字节完全相同的冗余 24.1 GB（364 组）**；
每张原图 171~197 MB，被各阶段目录以无损 PNG 重复存放（`data/列线清洗与结构识别/原图/`、
`data/纵向主框架恢复/原图/`、`runs/1035_visual_audit/04_candidates/原图/` 等）。

| 措施 | 回收 | 还原方式 |
| --- | --- | --- |
| 1. 相同字节改硬链接（去重） | 24.1 G | 同一 inode，内容零改动，任何一份路径都还在 |
| 2. 删各阶段目录里的 `原图/*.png` 副本 | ~15 G | 源头是 `data/raw_images/*.JPG`，重跑阶段脚本即得 |
| 3. 删已退役阶段的叠加图/预览图 | ~10 G | 纯函数产物，`rebuild_stages.py` 依序重跑即得 |
| 4. 保留不可再生物 | — | 见下 |

必须原地保留，一个字节都不动：

- `data/raw_images/`（267 M，30 张扫描件原件，唯一输入源）
- `runs/table_reconstruct/*_agnes读数.json`、`_单格重读.json`、`_列结构定稿.json`、`_行判定.json`
  （API 花费与用户核验结果，重跑要花钱且不可复现）
- `runs/table_reconstruct/视觉核验_20260916/视觉核验决策_20260916.json`（409 格逐格裁决台账）
- `runs/synthetic_gate/` 的 GT 与 30 张定稿基线（门禁比对基准）
- `outputs/Excel交付_最终_20260915/`（git 跟踪）
- `rollback/`（2.3 G，gitignore，删了就没了）

`.git` 5.3 GB 是历史里的大文件累积，工作区删除不会缩小它；重写历史的风险与收益不对等，不做。
改用 `.gitignore` 增补 `data/**/*.png`、`data/**/*.jpg`（保留 `.json` 与 `raw_images`）止住继续膨胀。

## 四、结构缺陷收敛（这一项才是"最初错、后来对"的病根）

实测：30 张表数值列共 3686 个"一格多值"，最差 1016 达 79%；
`(层界+子行线)/xlsx行数` 普遍 1.8~4.0，只有手工重建过的 1032/1042 是 1.2/1.5、多值 0%。

`src/table/track_rows.py::determine_rows` 把行线分三类：层界（`span≥0.6·数值区宽` 或全宽 `≥0.75·表宽`）、
子行线、弃线。数值区行线一断一淡就够不到门，落进后两类且永不复检；另有 y 相距 <40 px 直接去重，会吃掉薄层行。

改法一处，不在下游补脚本：

1. `sub_rows` 升为**候选层界**，不再当"文字下划线"丢掉。
2. 每个候选层界用两个独立证据裁决：与描述区行线是否共线；切这一刀后 Σ层厚 是否仍能对上深度链。
3. 40 px 去重改为按该列最薄行的像素高判定，不做全局常数。
4. `repair_1032.py` / `repair_1042.py` 里手工确认的规则回填进上述判据，两个脚本退役。
5. 30 张用同一套重跑行界。

验收：每张表 `多值格数 = 0` 且 `(层界+子行)/xlsx行数 → 1.0`，且 Σ层厚 对深度链闭合。
达标才允许重推内容与合并单元格；P0 哨兵（183 格 `@单`/`@条`）与数值列类型门禁在这之后一起做。

## 五、动手顺序与每步的还原保证

| 步 | 动作 | 还原 |
| --- | --- | --- |
| 0 | 打标签 `pre-cleanup-20260923`，`git status` 干净后生成 `manifest_清理前.md5`（覆盖 runs/data/outputs 全部文件的路径+字节+md5） | 清单本身即凭据 |
| 1 | 硬链接去重 | 内容不变，md5 清单复跑必须全绿 |
| 2 | 删原图副本与可再生位图 | 阶段脚本重跑即得 |
| 3 | `git mv` 废弃代码与旧文档进 `archive/`，写 4 份新文档 | 单条 revert 即可 |
| 4 | 抽 `rebuild_stages.py`，用 1015 从阶段 1 重放到阶段 6，与保留基线逐项对齐 | 重放通过才承认"可再生"成立 |
| 5 | 改 `determine_rows`，30 张重跑行界 | 分支 `stage-rows-rebuild`，`main` 不动 |

清理前后跑同一套证明：`pytest -q` 150 passed；md5 清单零实质差异；
`outputs/**` 与 git HEAD 零差异（前三步不碰交付物）。

第三步之前不执行任何删除。第一、二步只改链接与删可再生物，交付物 `outputs/` 与原件 `data/raw_images/` 全程不动。
