# 经验教训（lessons.md）

更新日期：2026-08-26

## 已确认的错误路线（勿再犯）

1. **分箱中位重采样生成列线轨迹**：在 bin 内混入平行碎片时中位被带偏 → 折线/扭曲。已证实（1035 col0 轨迹 131px 漂移/145 跳变，源段无此问题）。
2. **用固定 X / midx / 单一全局斜率做列线分组**：列线是倾斜的（斜率逐线不同，1035 左区 -0.075~+0.02），固定 X 或全局漂移校正会把同一条线分到相邻线带。
3. **段拼接用大容差桥接（A2：BRIDGE_PERP_TOL=100）**：吞并列、造横线/折线/跨列，画出原图不存在的线。指标达标 ≠ 结构正确。
4. **程序自证 / recall-precision 不能当结构正确**：这些指标不检测几何畸形（折线/横线/跨列）。
5. **在错误方向上加补丁**：方向错了，越打补丁越歪。应先回到第一性原理重新设计，而非在错误实现上调参。

## 工作方法教训（用户指出，必须执行）

- **长上下文导致核心原则被稀释**：重要原则（忠实数据源/连续性/不用 X 坐标/第一性原理）必须在每次工作前重读检查清单，不能依赖记忆。
- **错误框架的路径依赖**：一旦形成错误模式（如 X 分组），会反复复用。关键决策用 fresh context 子代理，避免被错误历史污染。
- **先验证假设再动代码**：每个假设先用只读数据量化验证（给出数值证据），确认后再实现。
- **验收必须含视觉健全性**：折线数/横线数/跨列数，与 recall/precision 并列。
- **与用户核对第四阶段质量**：应早点把第四阶段叠加图给用户看，而不是假定第四阶段也有问题。用户核验确认第四阶段没问题，问题在第五阶段。
